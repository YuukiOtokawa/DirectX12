# AIの作業ルール

## 対象

ルートの `AGENTS.md` から参照する、このリポジトリ全体の作業ルール。
ユーザーの現在の明示的な指示を優先する。

## 閲覧・調査

- 原則は読み取り専用。説明、設計案、修正例はチャットで提示する。
- 必要なファイルから読む。生成物、外部ライブラリ、別の作業ツリーを一括で走査しない。
- `.claude/worktrees/` などの別チェックアウトを、現在の実装と混同しない。
- 仕様書や過去の記録だけで実装を断定せず、保存済みのコードと呼び出し元を確認する。
- 不明点は「未確認」、設計上の提案は「提案」と記載する。

## 編集

- コードの変更やGit commit等はユーザーが行う。依頼のない編集、整形、移動、削除は行わない。
- 文書も同じ扱いとし、作成・更新を依頼された範囲に限って編集する。
- 編集前に対象の内容を読み、ユーザーの途中の変更を保持する。
- 関係のないリファクタリングや、リポジトリ全体のフォーマットを含めない。
- 編集が依頼された場合は既存の文字コード・改行に配慮する。C++の整形は `.clang-format` を参照する。
- 外部ライブラリ、ビルド生成物、個人用IDE設定を、目的の変更に巻き込まない。

## Git・実行

- 閲覧系のGitコマンドは指示なしで実行してよい。`git status`、`git diff`、`git log`、`git show`、`git blame`、`git branch`（一覧表示のみ）など、リポジトリや作業ツリーを変更しないものに限る。
- それ以外のGitコマンドは、明示的な指示や承認なしでは実行しない。`git fetch` もリモート追跡ブランチを書き換えるので、指示が必要な側に含める。
- 編集の依頼だけでは、commit・push・checkout・restoreなどの許可にはならない。
- ビルドやアプリ起動は生成物・設定を書き換えることがある。読み取り専用の調査では実行せず、検証を依頼された場合に行う。
- ビルド前にはプロジェクトの `PlatformToolset` とインストール済みVisual Studioを確認し、対応する開発環境を明示的に初期化する。

## 報告

- 日本語で、結論・根拠のファイル・影響を簡潔に伝える。
- 問題の指摘には発生条件と実際の影響を添える。
- 静的確認、C++ビルド、実行時シェーダーコンパイル、画面確認を分けて報告する。
- 未実行の確認を成功扱いにしない。未確認事項とユーザーが行う確認手順を示す。
