## 目的と対象範囲

`TODO.md` の「assertを避ける」と「ログ出力ウィンドウ」を扱う。

- アセットやシェーダーの読み込みに失敗しても強制終了せず、エディターを動かしたまま原因を表示して直せるようにする。
- 実行を続けられない失敗は、原因を示して明示的に終了する。
- 失敗の表示先が先に必要なので、ログ機構とログウィンドウを最初に実装する。

## 期待する挙動

### ログウィンドウ（エディターのみ）

前提: エディター起動後、既存のウィンドウと同様に表示され、`WindowManager` のチェックボックスで表示を切り替えられる。名前は `Log`。

| 操作・状況 | 結果 |
| --- | --- |
| 起動中（ImGui 初期化前を含む）に出たログ | バッファに残り、ウィンドウ表示後に確認できる |
| 新しいログが届く | 一覧の末尾に追加する。末尾を表示中なら自動で追従し、上へスクロール中は追従しない |
| 直前と同じレベル・本文のログ | 新しい行を作らず `(x3)` のように回数を増やし、時刻を更新する |
| レベルのチェックボックス（Info / Warning / Error）を切り替える | 一覧の表示だけを絞り込む。既定はすべて表示 |
| `Clear` を押す | バッファを空にし、エラー件数を 0 に戻す |
| 行を選ぶ | 一覧の下に本文全文を折り返して表示する。複数行のシェーダーエラーはここで読む |
| `Copy` を押す | 選択中の行の本文をクリップボードへコピーする。未選択なら無効 |
| Warning / Error がある | 行を色分けする（Warning は黄、Error と Fatal は赤） |
| Error 以上が 1 件以上ある | タイトルを `Log (3 errors)` のようにする。ドッキングのタブでも気づける |
| ログが 1 件もない | 空の一覧を表示する |
| バッファが上限（1024 件）に達した | 最も古い行から捨てる。エラー件数は捨てても減らさない |

一覧は 1 ログ 1 行で、複数行の本文は最初の行だけを表示する。`ImGuiListClipper` で表示範囲だけを描くためで、行の高さを揃える必要がある。

### レベルの使い分け

| レベル | 用途 | 例 |
| --- | --- | --- |
| Info | 通常の記録 | 将来の読み込み完了の通知など |
| Warning | 代替処理で続行し、見た目への影響が小さい | シェーダーメタデータがなく既定値を使った |
| Error | 機能の一部が動かないが続行する | テクスチャの読み込み失敗、シェーダーのコンパイル失敗 |
| Fatal | 終了する | デバイス作成失敗、デバイスロスト |

本文は既存のデバッグ出力に合わせて英語で書き、原因となったパスと `HRESULT` を含める。

## 処理の流れと所有権

### ログ

- バッファは `Log.cpp` の内部（`EngineCore.dll`）が持つ。`RenderManager` に依存しないので、エンジン初期化前や失敗中でも書ける。
- `Write` は mutex で保護し、バッファへの追加と `OutputDebugStringA` への出力を行う。Release でも動く。
- ウィンドウは `GetRevision` が変わったときだけ `Snapshot` を取り、コピーを自分で持つ。毎フレーム文字列をコピーしないため。
- ログウィンドウは GPU リソースを持たない。

### 例外と終了

- `ThrowIfFailed` と既存の例外は、`Editor/Main.cpp` と `Player/Main.cpp` の `catch` で捕捉する。`try` を初期化（`make_unique`、`Initialize`）と `Update` まで広げる。
- `catch` が `Log::Write(Fatal, ...)` を呼び、`MessageBox` を出して終了する。記録を 1 箇所にまとめ、二重記録を防ぐ。
- 部分的に記録したフレームは提出しない（`Main.cpp` の既存の方針）。
- `exit()` は使わない。終了コードは 1 にする。
- 初期化の失敗で `RenderManager` がないときは、`Editor/Main.cpp` の `WndProc` は `WM_SIZE` で参照しない。`Player/Main.cpp` は `g_GameApp` の確認で既に防いでいる。
- `RenderManager` のコンストラクタで例外が起きたら `m_Instance` を `nullptr` に戻す。デストラクタが呼ばれず、破棄後のポインタが残るため。
- その後に破棄されるメンバーのために、`TEXTURE` と `RENDER_TARGET` のデストラクタは `GetInstance()` が `nullptr` なら解放しない。

### テクスチャの読み込み

1. `GetAvailableCount()` を確認する。
2. `LoadDDSTextureFromFile` と `WriteToSubresource` を行う。失敗したら `nullptr` を返す。
3. 成功してから SRV を確保して `TEXTURE` に設定する。

`make_unique` で作った `TEXTURE` の `SRVIndex` は 0 になるので、対策なしに途中で戻るとデストラクタが使用中の 0 番を解放する。`RENDER_TARGET` も同じなので、無効値の導入と確保順の変更を合わせて行う。

1. **ログ機構とログウィンドウ**: `Log.h/.cpp`、`LogWindowController` を追加する。既存の `OutputDebugStringA`（`MeshAsset.cpp:74`、`ShaderMetadata.cpp:124`、`RenderManager.cpp:1225,1256`）を `Log::Write` に置き換える。この段階では `MessageBox` と `assert` は残す。
2. **`Main.cpp` の例外処理**: `try` の拡張、`catch` での Fatal 記録、`WM_SIZE` の null 確認。

5. **シェーダーと PSO**: `MessageBox` の撤去、`SetPipelineState` の `bool` 化と呼び出し側のスキップ。
   - 実装時に決めたこと: コンパイル失敗のログは 1 行目に「エントリ、ターゲット」と最初のエラー行（`Foo.hlsl(12,5-10): error X3004: ...`。ディレクトリは落とす。エラー行がなければシェーダーのパス）、2 行目以降にコンパイラの出力全文を置く。`SetPipelineState` は失敗してもログを出さない（作成時に記録済みで、毎フレーム出ると件数が増え続けるため）。

   - `CreatePipeline` の `mbstowcs_s` も `_TRUNCATE` にした（第 4 段階の `TextureLoader` と同じ理由）。
   - ユーザーの依頼で、MeshRenderer のインスペクターに `Recompile` ボタンを追加した（`MeshRendererDrawer.cpp` の `RecompileShader`）。設定中のシェーダー（未設定なら `Geometry.hlsl`）を `ReloadPipeline` で作り直し、成功したらマテリアルを新しいメタデータで構成し直して、名前と型が同じプロパティの値を引き継ぐ。失敗したら前の PSO と値のまま。

   - ビューのリサイズ: 新しいターゲットを作れてから差し替え、失敗したら Error を記録して元のサイズのまま。失敗が続くと、ビューの大きさが変わるたびに再試行して記録する（同じ本文は回数でまとまる）。
   - 定数サイズ: `SetConstant` は大きさが不正（0 または 512 超）なら `false` を返して何もしない。毎フレーム呼ばれるのでログは出さず、`Material::SetShader` で 1 回だけ記録する。`MeshRenderer` はその物体を描かず、ポストプロセスはそのパスを飛ばす。
   - メッシュの読み込み: `LoadMesh` は読み込み中の例外を捕捉して失敗として扱い、頂点が 0 個のメッシュも失敗にする。

## 現在の実装と差異

静的確認の結果（2026-11-02、`master` の作業ツリー）。

実装済み:

- `Common.props:34` が Release で `NDEBUG` を定義する。Release では `assert` が消え、失敗は素通りする。
- ウィンドウの基盤: `Editor/GUIController/WindowManager.cpp`、`ImGuiWindowController.cpp`。タイトルは `m_WindowName + "###Window_" + ID` なので、ID を変えずに `m_WindowName` を変更できる。
- シェーダー失敗時の描画スキップと旧 PSO の維持: `MeshRenderer.cpp:71`、`RenderManager.cpp:776,1788`。

未実装:

- 「実装順序」の第 1〜第 6 段階はすべて実装済み。残っている `assert` は「変更しないもの」の 4 箇所だけ。

第 4 段階で仕様に追加したこと:

- `TextureLoader::Load` は 2D 以外の DDS を読まない。ボリュームテクスチャなどで `subresouceData` の範囲外を読むため。
- `mbstowcs_s` を `_TRUNCATE` にした。長すぎるパスでの強制終了を避け、読み込み失敗として記録するため。
- テクスチャなしのオブジェクトは、前のオブジェクトのテクスチャではなく白で描画するようになった（`MeshRenderer.cpp`）。

第 4 段階の確認中に見つかった問題:

- MeshRenderer の `Select Texture` で同じマテリアルに 2 回目のテクスチャを読み込むと、デバイスロスト（`DXGI_ERROR_DEVICE_HUNG`、TDR）で終了した（ユーザーの報告。`field004.dds` を 2 回）。直前に D3D12 のエラーは出ていない。
- 原因の推定: `Material::SetTextureBaseColor` が古いテクスチャを即時解放していた。同じフレームで記録済みの描画や、実行中の前のフレームがまだ使っている。`SetTexture` と同じく `DeferReleaseTexture` で遅延解放するよう修正した（未コミット）。修正後にユーザーが確認し「問題なさそう」（2026-11-04）。
- 同じ種類の問題が `MeshFilter::LoadModel` にもあった。`delete m_VertexData`（テクスチャを持つ）と、`SetVertexData` での頂点・インデックスバッファの差し替えが即時解放だった。`RenderManager::DeferRelease`（`std::shared_ptr<void>` を受ける汎用の遅延解放）を追加して、3 つとも遅延解放にした（未コミット）。修正後にユーザーがビルドして確認し「問題なさそう」（2026-11-04）。
- 未修正: オブジェクト削除時（`MeshFilter` のデストラクタ、`Material` のテクスチャ）も即時解放のまま。削除はコマンド記録の前に行う（`ObjectManager::FlushRemovedObjects`）ので同じフレームの記録とは重ならないが、実行中の前のフレームとは重なりうる（未確認）。

既知の再現しやすい問題:

## 未決定事項

推奨案で進める場合は、この章の推奨どおりに実装する。

1. **内部シェーダーが失敗したとき**: 描画を飛ばして続行するように実装した（推奨案）。ただし Player（`Layout::Distribution`）の `ScreenToBackBuffer` は何も表示できないので、`RenderManager::Init` で致命的扱いにした。内部シェーダーには再読み込みの手段がないので、直した後は再起動が必要。
2. **読み込みに失敗したテクスチャの見た目**: 白で実装した（推奨案）。マゼンタは「未設定」と「失敗」を区別する仕組みが必要なので後回しにする。
3. **ダイアログの選択肢**: 一度 `*.dds` だけに絞ったが、ユーザーの依頼で PNG などの読み込みに対応したので、`*.dds;*.png;*.jpg;*.jpeg;*.bmp;*.tga` にした（`TextureLoader.cpp` の `LoadImageTextureFromFile`。リンク済みの DirectXTex を使い、RGBA8 に変換してミップを生成する。sRGB のフォーマットにはしない）。
4. **ログウィンドウを閉じているときに Error が出た場合**: 推奨は自動で開かない。作業中のレイアウトを変えないため。気づきにくくなるので、運用して問題があれば見直す。
5. **Player のログ**: 推奨は今回はファイルに出さない。`OutputDebugStringA` とバッファのみなので、配布版で原因を見るには Fatal の `MessageBox` に頼ることになる。
6. **非 ASCII の表示**: ImGui に日本語フォントを追加していないので（`ImGuiController.cpp` に `AddFont` なし）、日本語を含むパスは一覧で正しく表示されない見込み。推奨は今回は対応しない。`FilePicker.cpp:38` はパスを UTF-8 で返す一方、`TextureLoader.cpp:61` は `mbstowcs_s` で変換するので、日本語を含むパスの読み込み自体が失敗する可能性もある（未確認）。
7. **AssetPipeline のエラー**: `ObjImporter.cpp`、`FbxImporter.cpp` は `fprintf(stderr)` で報告するので、エディターでは見えない。AssetImporter でも使うライブラリなので、推奨は今回は変更せず、`LoadMesh` のログ（パスのみ）で伝える。詳しい原因は表示されない。
